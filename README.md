# 音乐档案 · 听过，练过，留下过

这是可直接替换原 Music Notebook 静态网站的完整代码，不需要构建工具。
账号登录、公开/私有权限暂未实现，所有发布到公开仓库/网站的资料仍是公开的。

## 一、替换到原 GitHub 仓库

1. 在旧网站点击「导出备份」，保存一份带附件的 JSON。先保留，暂时不要导入。
2. 解压这个代码包，打开里面的文件。将根目录的 HTML、JS、CSS、README.md、content.example.json 和 `.nojekyll` 上传到原 `music-notebook` 仓库根目录，替换同名文件。新增的 `archive-*.js` 和 `archive.css` 必须一起上传。
3. 不要删除或替换你原来的 `content.json` 和 `assets/`。本包没有 content.json，不会拿示例数据覆盖你的知识资料。
4. 等 GitHub Pages 部署结束后，用原网站地址打开。若仍是旧界面，刷新或清除页面缓存后重试。
5. 旧数据会自动补上课程结构：原分类成为课程，原页面成为课次；原知识块、组件编号和附件引用保留。你可进入目录管理修改课程/章节名称。
6. 如果在同一浏览器、同一网站路径更新，会先恢复本机草稿；换设备先读取 GitHub 内容，或导入第1步的完整备份。

不要更换仓库路径来替换页面：本机草稿按原网站路径保存。GitHub 网页上传时可先上传普通文件；隐藏文件 `.nojekyll` 原仓库已有则保留即可。

## 二、主页和课程目录

- 名称暂用「音乐档案」，副标题为「听过，练过，留下过」。可在代码 `archiveSettings.title` 中改名称。
- 主页展示课程知识、练习库、乐器练习、作品档案四个入口，新增课程自动出现在导航地图上。
- 课程目录按「课程 → 章节 → 第几课 → 知识点」组织，知识点里继续使用原白板的文本、鼓、音符块、图片、音频组件。
- 目录顶部「＋」弹出新增窗口，按当前选中位置默认选择下一层；允许切换新增类型和所属位置。
- 「⋯」进入目录管理：修改名称、左侧减号删除。点「完成」退出，不显示额外目录管理状态栏。
- 删除课程/章节会连同下级内容删除，先显示确认范围，删除后可撤销。删除完最后一个课次也不会使主页崩溃。
- 搜索框保留名称搜索；左侧原知识块/组件切换按钮不再常驻。
- 目录左侧的主页图标一次点击返回主页。

## 三、练习库

### 加入、整理、知识图

- 知识点旁点「加入练习库」，进入未分类。已有节点不会重复创建。
- 未分类默认展示最新6个，点击查看更多展开其余内容。
- 拖到分类卡片完成归类；拖到「＋新建分类」输入名称后归入；手机可通过卡片「⋯」选择分类。
- 移出练习库不会删除原知识及历史记录；删除分类也不会删除知识点。
- 3D知识图支持拖动旋转、滚轮/按钮缩放、点选节点，以及下拉选择节点。
- 蓝色表示已分类，灰色表示未分类。颜色不表示掌握程度。未分类知识照常练习、加入计划。
- 虚线表示同课结构关系；实线表示你手动确认的知识关联，前置关系有箭头。
- 位置根据课程与已确认关联生成，与分类颜色无关。大量节点时隐藏部分标签，选中后展开相关信息。
- 在知识点「⋯」或图中点击「关联 / 重点」，设置关联、前置基础、通用程度和重点。没有使用付费 AI 或臆造语义关系。

### 今日计划与推荐

仅用于复习，不提供“新学/混合”切换。

- 先选方式：按课程、按主题、智能推荐、我的练习单。
- 按课程可选整门课、章节或课次，再从候选中勾选具体知识。
- 按主题依据课程名称、知识标签及已确认的关系寻找内容，包含已分类/未分类。
- 智能推荐包括补薄弱、防遗忘、巩固基础、围绕一个点、综合推荐。
- 补薄弱依据没看懂和反复疑问记录；防遗忘依据上次练习时间；基础/通用依据你设置的通用程度和前置关系。它们是透明的排序规则，不是诊断或算法判定你已经掌握。
- 候选项显示理由，可勾选并调整顺序，确认后才生成今日清单。
- 缺少已确认的前置知识时会提示，是否保留当前选择由你决定。
- 自建练习单像歌单，引用已有知识点；可调整顺序，一键生成当日计划。同一知识可以属于多份练习单，不重复计数。

### 计时、反馈与历史

- 点击开始练习后计时，支持暂停、继续、结束；打开网页不会自动增加次数。
- 结束后提供「还要再练 / 没看懂 / 比较熟练」。不选、直接完成，或关闭这个反馈窗口，默认保存“还要再练”。
- 每次保存一条记录，统计有效时长和练习次数，不删除以前的记录。
- 每个节点的「⋯」可以查看练习历史或手动补记。
- 完成一次计划任务只标记今天该项完成，不把它立即排回今天的队列；“还要再练”进入以后计划的候选。
- 刷新后的未结束练习恢复为暂停，关闭网页的时间不算有效练习时间。

## 四、乐器练习

初始有电吉他、键盘，可新增其他乐器。

- 三个视图：练习计划、练习记录、待练清单。
- 待练清单中的同一条目可多次安排；按是否已练过分为准备练和继续练。
- 计划支持日期、目标分钟，及从选定日期起连续7天的安排；显示今日和本周计划。
- 实际练习支持计时或手动补记；保存实际分钟、三种反馈、笔记和可选附件。
- 今日完成不等于熟练；未熟练的条目继续留在待练清单。
- 练习录音值得留作成果时，选择“存入作品档案”，创建作品或归入已有作品，不复制附件文件。

## 五、作品档案

- 每件作品一张卡片，可选择多个类型：演唱、编曲、作曲、乐器、其他。
- 每个阶段记录名称、日期、音频/视频/图片/乐谱等附件、变化或问题。
- 新阶段按日期在前排列，旧版本不覆盖。
- 可指定代表版本；并排比较两个阶段的文件与说明。对比时同时只播放一段媒体。
- 作品和阶段支持修改、删除与撤销。附件单个最大50 MB，存本机 IndexedDB。

## 六、一键保存到 GitHub

1. 创建 Fine-grained personal access token，只选择 `music-notebook`，Contents 设置为 Read and write。
2. 点击顶部「连接 GitHub」，填写用户名、仓库、分支、令牌，再点「连接并验证」。
3. 如果想继续另一台设备的数据，先点“读取 GitHub 内容”；读取会替换本机档案，先备份未同步修改。
4. 连接后顶部变为“保存到 GitHub”，编辑完直接点击。若首次连接的仓库已有数据，保存将以当前本机档案更新它；确认本机内容是你想保留的版本。
5. 课程、计划、记录、作品与本地附件在同一次 Git 提交中保存，其他设备更新过内容时拒绝覆盖。失败时本机修改仍保留。
6. 可选择在当前标签页会话记住连接，刷新仍可用；关闭标签页或断开后重新连接。令牌不进入备份、代码或 content.json。

同步配置窗口可通过按 Esc 或点击窗口外关闭。保存内容后，公开页面要等待 GitHub Pages 部署完成才会更新。

GitHub 保存的是网站的档案数据与附件；修改网站代码本身时仍需上传代码文件。视频和音频较多时应留意仓库体积；本版不添加任何用户登录/权限服务。

## 七、本机保存与备份

- 沿用原本的本机自动保存和完整 JSON 备份；新增数据一起保存。
- 完整备份包含知识图片/音频、乐器记录附件、作品阶段附件。原设备的本地文件优先；已同步的附件可从公开网站读取后纳入备份。
- 文件只能保存在当前浏览器时，请先导出或同步再清理浏览器数据。
- 导入完整备份最大300 MB，单个附件最大50 MB。
- 示例内容仅在无本机草稿且仓库没有 content.json 时显示。
